# An include's with: takes a {from, if_skipped} binding as a plain object, and nothing says so

## Problem

In a `command:` or `script:` node, a `with:` value written as `{from: "$a.output.v", if_skipped: null}` is a binding: it resolves to `$a.output.v`, or to `null` when `a` was skipped.

The same object written in an `include:` node's `with:` loads and validates without a message, but it is not a binding there. The included workflow receives the object itself, with the keys `from` and `if_skipped`, and the `if_skipped` value is never used.

The source on `dev` says this is the rule: `packages/workflows/src/schemas/node-bindings.ts` has "Include/workflow `with:` maps have no directive, so objects there stay ordinary JSON literals." What we report is not the rule but that breaking it is silent.

## Why

An author who writes a binding in an include's `with:` cannot tell from load, validate or the run that it did nothing. We found it only when an included workflow saw a skipped upstream value it was not expecting.

`direction.md §schema-width` asks that capability mismatches "warn loudly, never silently no-op".

## Desired outcome

Writing a binding object in an include's `with:` is either honoured as a binding or rejected at load with a message that names the field.

## Acceptance

- [ ] A workflow whose `include:` node has `with: { x: { from: "$a.output.v", if_skipped: null } }` either fails `archon validate workflows` naming `x`, or the included workflow receives `null` for `x` when `a` is skipped.
- [ ] The workflow-language reference says which of the two holds.

## Evidence

### Reproduction

1. Parent workflow: node `a` with `when:` that is false, so it is skipped; node `child` with `include: <child workflow>` and `with: { x: { from: "$a.output.v", if_skipped: null } }`.
2. Child workflow: one `script:` node that prints the input `x`.
3. `archon validate workflows` passes. Run the parent. The child receives the object itself instead of `null`.

We saw this in our own workflows; the minimal form above is how we would show it, and we have not run that exact form.

### Environment

- Archon version or commit: seen on an earlier pinned revision; the quoted source lines are unchanged on `dev` at `40e531e7b`
- Platform or adapter: CLI
- Database: SQLite
- OS: Linux

## Constraints and related work

- Related issues or PRs: #3306 (language-surface gaps around what an include may reference), #5359
- Our workaround: a `script:` node in the parent takes the binding in its own `with:` and re-emits an explicit value, and the include reads that node's output instead. It exists only to carry `if_skipped` across the include.
- Solution steering: Hint — a load-time rejection would be enough for us.
