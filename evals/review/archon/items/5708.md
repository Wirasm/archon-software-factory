# Chat notifications and the watch show the outcome a run completed with, named outcomes included

## Desired outcome

A chat notification about a completed run carries the outcome the run completed with, including a named outcome such as `built` or `return`.

## What happens today (after PR 5698)

PR 5698 writes a run's declared outcome once, at completion, into `completed_outcome`, and leaves the legacy boolean `outcome` null for a named value. Three readers still read only the legacy column:

- the terminal attention notice sent to chat (`packages/server/src/chat-host/attention-destination.ts`),
- the live terminal run event (`packages/server/src/chat-host/run-events.ts`),
- the chat contract's schema, which cannot represent a named value (`packages/chat-contract/src/run-events.ts`).

The review of PR 5698 ran both: a completed run with `completed_outcome: 'built'` produced a terminal notice with no outcome, and `chatAuthoredOutcomeSchema.safeParse('built')` fails. The attention watch's terminal line is in the same position.

These were left out of PR 5698 on purpose to keep that change to the store, the CLI and the console; it was already large.

## Acceptance

- A named completion appears in the chat attention notice and in the live terminal event.
- The chat contract carries named values; a boolean outcome still round-trips.
- The watch's terminal line shows the completed outcome.
- Every reader uses the one outcome display rule the engine owns, or is held to it by a conformance test.

## Invariants

- No reader derives an outcome before the run completes.
- A run with no declared outcome shows none.

Depends on PR 5698.
