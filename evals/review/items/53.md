# Escape cancels commenting and also closes the map trace

Filed by Wirasm.

<!-- archon-discovery comment-escape-closes-map-trace -->
## Problem

While walking a map trace, entering comment mode and pressing Escape outside an input cancels commenting and also exits the trace. The person loses their current step even though the Comment control advertises Escape as its cancellation action.

## Evidence

Verified by reading base `ac81d0303bdf7d2520ce06b4a2b9809cd4909c2b`:

- `skill/recipes/map/view.html:419-427` handles document keydown events. Outside inputs and runtime cards, Escape clears `tr` when no node is selected, stops playback and renders the map.
- `assets/runtime.js:214-219` manages comment mode and labels the active control with `Esc`.
- `assets/runtime.js:898-904` independently handles Escape on the window and calls `setMode(false)`. It does not consume the event before the map's document handler runs.
- `skill/recipes/map/view.html:396` starts a trace at step zero by default, so reopening does not preserve the discarded position.

A single bubbling Escape event therefore reaches both handlers. The run's recorded browser evidence corroborates this for the map and its earlier base; this decision used code reading and ran no tests or probes.

## Why and why now

Cancelling a temporary comment interaction should preserve the view the person was commenting on. The conflicting handlers remain at the base. There is no dedicated direction document; preserving context supports the README's use-and-comment workflow. Closed issue #18 and PR #21 concern Comment-button placement, not Escape ownership. Tracker searches found no covering issue or pull request.

## Outcome

Escape used to cancel comment mode leaves the map trace and selected step intact. Once commenting is inactive, the map's ordinary Escape behavior remains available.

## Invariants

Preserve ordinary map keyboard navigation, node dismissal and trace dismissal. Preserve standalone and embedded commenting, comment-editor cancellation and the existing embedded Escape behavior. Trace navigation remains local view state.

## Acceptance

- Start a trace, advance beyond step zero, activate commenting and press Escape outside an input: commenting ends while the trace and step remain unchanged.
- Press Escape again with commenting inactive: normal map dismissal works.
- Cover standalone and embedded jellies and retain comment-editor cancellation.
- Add one focused browser regression using the real runtime and map recipe; run `cargo test` and `cargo clippy`.
