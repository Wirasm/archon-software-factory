# Admit backtest, 2026-11-16

Question: given the draft policy (`policy-archon.md`), does an agent make the call an operator
would have made: start this item automatically after triage, or ask first?

## Method

- 34 past items of coleam00/Archon that went through the factory between 11-13 and 11-16.
- Two fresh agents each judged half, blind: only the item as captured at intake, what triage
  concluded (recommend, why, summary, size), the policy and `prompt.md`. No code, no history.
  Eleven items had no triage record; for those the size is the one their plan gave.
- A third agent built the label for each item from the records (run outputs, the state log, the
  overrule log, GitHub), without seeing the judges. "Should have been auto": merged with no ruling,
  no ask and no harm (an overrule of a stage alone still counts as auto). "Should have asked": a
  maintainer or the managing agent had to decide something the item did not settle, a stage ended
  as an ask, the item was parked or closed unbuilt, or the run did harm outside its checkout.
- 5 of the 34 have no label: three are in flight, two are unclear.

## Result, 29 labelled items

| | judged auto | judged ask |
|---|---|---|
| should have been auto (12) | 9 | 3 |
| should have asked (17) | 4 | 13 |

Agreement 22 of 29. Of 13 items the judge would have started automatically, 9 were clean.

## The four it would have started and should not have

- **5720** (the builder killed processes on the operator's machine while testing): nothing in the
  item says a test would signal processes. The policy line on process signalling did not fire
  because the item is about restarting a run. A judgment on the item text cannot see how a
  builder will test.
- **5659, 5738**: a later stage raised a question, or the managing agent ruled, on a point the
  item did not settle. Both judges were only medium sure.
- **5732**: the label rests on an ask the managing agent called "one the rules already answer".
  Arguably auto was right.

## The three extra asks

- **5681, 5701**: size m. The policy's size line is what asked; both went through clean.
- **5739**: judged to change a default users rely on; it went through clean.

## What this does and does not show

- One run, 29 items, one draft policy written the same day by the agent that managed these
  items, so the policy is fitted to them. The labels were built by one agent and several calls
  move them: counting four pre-build answer files as rulings turns four items from clean to
  needed a decision.
- Three captured item texts contain decisions written after work started (5660, 5688, 5709);
  all three were judged ask, and the leak could have helped.
- Not shown: how the judgment does on items from outside authors, or on a project with no policy.
