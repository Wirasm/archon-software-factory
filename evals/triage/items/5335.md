# Codex nodes reject omitted nullable MCP status fields

Filed by MeXaaR.

## Problem

A Codex workflow node fails before its first model turn when `mcpServerStatus/list` omits `pluginId` and `toolsError`. Reproduced with Archon 0.13.0 and an explicitly configured Codex CLI 0.165.0; the same strict schema remains on `dev`.

The error is:

```text
Cannot scope the node's Codex plugins and MCP servers:
unexpected `mcpServerStatus/list` response
Expected string, received undefined at data[0].pluginId and data[0].toolsError
```

## Reproduction

Run a single Codex prompt node with ambient MCP servers configured in the native Codex home. The failure occurs during scope validation, before `turn/start`, even when those servers are disabled for the node. No particular model is required for this parsing failure.

Codex 0.165.0's `app-server generate-json-schema` lists neither `pluginId` nor `toolsError` as required properties of `McpServerStatus`. Archon's `scope.ts` accepts explicit nulls but rejects their absence.

## Expected outcome

Accept omitted nullable status fields by normalizing them to null. Keep rejecting malformed non-null values and live undeclared or plugin-owned MCP servers. Preserve native Codex configuration and the node's capability boundary.

## Acceptance

- Missing either or both nullable fields no longer fails the response parser.
- Explicit nulls remain accepted; malformed values remain rejected.
- Disabled ambient servers pass, while live undeclared servers and plugin-owned servers remain blocked.
- Targeted tests reproduce the failure before the fix and pass afterwards.

Related implementation: #3621.
