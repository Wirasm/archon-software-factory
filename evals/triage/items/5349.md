# Workflow nodes: expose the commit the run started from as a variable

Filed by robertmeisner.

## Problem

Archon records the commit a run started from as `checkout_baseline` (`archon workflow get <run-id> --json`; see "The run's starting checkout" in the CLI reference). A node inside the run cannot read that value without calling the CLI:

- `$BASE_BRANCH` names a branch, not a commit, and the branch can move while the run is in progress.
- `ARCHON_NODE_EXECUTION` carries `invocation.checkoutStart`, which is the commit the current node started at. Once an earlier node has committed, it is no longer the commit the run started from.

## Why

A node that reviews, summarises or checks everything a run changed needs a fixed lower bound for `git diff` or `git log`. Today each workflow has to work this out itself: call `archon workflow get "$WORKFLOW_ID" --json` from inside the node and parse `checkout_baseline`, or have a first node save `git rev-parse HEAD` to `$ARTIFACTS_DIR` for later nodes, which depends on that node running before anything commits.

## Desired outcome

Bash and script nodes, and prompts, can read the commit the run started from: the same value as `checkout_baseline.commit`.

## Acceptance

- [ ] A bash node that runs after another node has committed can print the run's starting commit, and the value equals `checkout_baseline.commit` from `archon workflow get <run-id> --json`.
- [ ] The value stays the same when the run is resumed, as `checkout_baseline` does.
- [ ] The variables reference documents the value, including what it holds when the run's checkout is not a Git repository.

## Evidence

### Reproduction

In an empty directory, with Git Bash on Windows (any POSIX shell should behave the same):

```bash
mkdir archon-demo && cd archon-demo
git init -q -b main
git init -q --bare ../archon-demo-origin.git
git remote add origin ../archon-demo-origin.git
mkdir -p .archon/workflows
cat > .archon/workflows/start-commit.yaml <<'EOF'
name: start-commit
description: A later bash node looks for the commit the run started from
nodes:
  - id: change
    bash: git commit -q --allow-empty -m "work done by the run"
  - id: later
    depends_on: [change]
    bash: |
      echo "HEAD now: $(git rev-parse HEAD)"
      echo "this node started at: $(printf '%s' "$ARCHON_NODE_EXECUTION" | grep -o '"commit":"[0-9a-f]*"' | head -1)"
      env | grep -E '^[A-Z_]*(COMMIT|BASELINE)[A-Z_]*=' || echo "no variable holds the run's start commit"
EOF
git add -A && git commit -qm "add workflow" && git push -q -u origin main
echo "run starts at: $(git rev-parse HEAD)"
archon workflow run start-commit > run.log 2>&1
run=$(archon workflow runs --json --limit 1 | grep -m1 -o '[0-9a-f-]\{36\}')
archon workflow get "$run" --json --verbose | grep '"outputPreview"'
archon workflow get "$run" --json | grep -A3 '"checkout_baseline"' | grep '"commit"'
```

### Observed

`A` is the commit the run started from and `B` the commit made by the `change` node:

```text
run starts at: A
      "outputPreview": "",
      "outputPreview": "HEAD now: B\nthis node started at: \"commit\":\"B\"\nno variable holds the run's start commit"
    "commit": "A",
```

`checkout_baseline.commit` is `A`, but the `later` node can only see `B`.

### Expected

The `later` node can read `A` from a variable, as it reads `$WORKFLOW_ID` or `$ARTIFACTS_DIR`.

### Environment

- Archon version or commit: CLI v0.13.2 release binary (`archon-windows-x64.exe`, commit b8d01782). The code paths below are unchanged on `dev` at 755cfad79ac8.
- Platform or adapter: CLI
- Database: SQLite
- OS: Windows 11 x64, Git Bash

## Constraints and related work

- Must remain true: `checkout_baseline` is observed once, before the first node, and never rewritten. The new value should come from that record rather than from a new sample.
- Related issues or PRs: none found.
- Solution steering: Hint. `buildExecNodeEnvironment` in [`packages/workflows/src/exec-environment.ts`](https://github.com/coleam00/Archon/blob/755cfad79ac8c66b03768479fcf7acdcab8691a3/packages/workflows/src/exec-environment.ts#L39-L64) builds the bash and script environment, and `substituteWorkflowVariables` in [`packages/workflows/src/workflow-variables.ts`](https://github.com/coleam00/Archon/blob/755cfad79ac8c66b03768479fcf7acdcab8691a3/packages/workflows/src/workflow-variables.ts#L95) the prompt variables. Neither has a value for the run's starting commit; the only commit a node receives is its own `checkoutStart` inside `ARCHON_NODE_EXECUTION`. A variable such as `$RUN_START_COMMIT` (the name is only a suggestion), filled from the run's `checkout_baseline.commit` and empty when there is none, would cover this.
