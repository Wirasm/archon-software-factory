# feat(cli/providers): Microsoft Foundry (Azure) support — setup wizard, .env.example, and Claude provider env passthrough

Filed by tbrandenburg.

## Problem

An enterprise user running Claude through Microsoft Foundry (Azure) has no supported way to configure Archon for it. Claude Code needs `CLAUDE_CODE_USE_FOUNDRY=1`, `ANTHROPIC_FOUNDRY_RESOURCE` (or `ANTHROPIC_FOUNDRY_BASE_URL`), either `ANTHROPIC_FOUNDRY_API_KEY` or an Entra ID login (`az login`), and optionally `ANTHROPIC_DEFAULT_SONNET_MODEL`, `_OPUS_MODEL` and `_HAIKU_MODEL` to pin deployment names. Nothing in `packages/cli`, `packages/providers`, the docs site or `.env.example` mentions Foundry. The setup wizard (`packages/cli/src/commands/setup.ts`, `claudeAuthType` at line 150) offers only global login, an Anthropic API key and an OAuth token, and `claude /login` is disabled on Foundry. A Foundry user hits "Not logged in" with no documented way out.

Claude Code itself does the Azure routing. Host runs pass the process environment to the Claude subprocess (`buildRequestSubprocessEnv`, `packages/providers/src/claude/provider.ts`), so the variables probably work when set by hand in `~/.archon/.env`. That has not been run; it is the first thing to confirm.

## Why it matters

Archon's governed, self-hosted pitch lands with enterprises, and Azure is a common home for their model access. They need a documented path, not source reading.

## Why now

Credentials are now provider-declared catalogs shown as per-agent cards in the console (#1954, #1955, #1956, closed). Foundry is a new credential shape, so the decision on where it belongs is cheapest to make against that model, before a wizard branch gets added to the old flow.

## Desired outcome

A Foundry user can configure Archon from documentation or setup, and a run reaches Azure through Claude Code.

## Open decision (settle first)

Is Foundry (and the same-shaped Bedrock and Vertex modes, which also have no references today) a documented environment recipe, or an entry in the Claude provider's credential catalog (#1955) with a console card and a wizard path? The recipe is smaller and honest if Archon only passes env through. The catalog entry is right if Archon should validate the fields and keep secrets in its credential store.

## Invariants

- Archon makes no Azure calls; Claude Code does. Archon only delivers configuration.
- Secrets use the same handling as the existing Claude API key: password prompt, never logged, not written outside the credential path.
- Container runs keep the env-isolation rule: only the Archon-managed env bag crosses the boundary, so Foundry values must travel through `requestOptions.env`, not host `process.env`.
- Provider auth contract is preserved: no relabeling a provider identity to reuse credentials.

## Acceptance

- Documentation (or catalog entry) lists every required Foundry variable and the two auth methods.
- A Foundry configuration is verified to reach a Claude run on a host install, and the result is recorded on this issue.
- Whichever path is chosen, `archon setup` no longer leads a Foundry user into the global-login or Anthropic-key dead end.
- Tests cover whatever serialization or validation the chosen path adds.
