# workflow get --json: node summaries hold only the first 200 characters of a node's output

Filed by robertmeisner.

## Problem

`archon workflow get <run-id> --json --verbose` reports each node's result as `outputPreview`: the first 200 characters of the node's output followed by `...`. A node's complete output is only in the raw event rows (`--events`, `node_completed` → `data.node_output`), and the CLI reference says raw events are "not the recommended integration surface". The run's transcript (`archon workflow logs <run-id>`) keeps only the last 2000 characters (`stdout_tail`).

## Why

A script that starts a workflow and then reads what one of its nodes produced, for example a JSON result printed by the last node, cannot get that output from the run's JSON. It has to parse raw events or have the workflow also write the same output to a file in `$ARTIFACTS_DIR`.

## Desired outcome

A supported JSON surface returns a completed node's full persisted output.

## Acceptance

- [ ] `archon workflow get <run-id> --json --verbose`, or a documented option of it, returns the full persisted output of a completed node.
- [ ] When the persisted output is itself incomplete (output over the persisted size limit), the result says so.
- [ ] Human-readable output keeps its short preview.

## Evidence

### Reproduction

In an empty directory, with Git Bash on Windows:

```bash
mkdir archon-demo && cd archon-demo
git init -q -b main
mkdir -p .archon/workflows
cat > .archon/workflows/long-output.yaml <<'EOF'
name: long-output
description: A bash node that prints 5000 characters
nodes:
  - id: big
    bash: "printf 'x%.0s' $(seq 1 5000)"
EOF
git add -A && git commit -qm "add workflow"
archon workflow run long-output --no-worktree > run.log 2>&1
run=$(archon workflow runs --json --limit 1 | grep -m1 -o '[0-9a-f-]\{36\}')
archon workflow get "$run" --json --verbose | grep -o '"outputPreview": "[^"]*"' | tr -cd 'x.' | wc -c
archon workflow get "$run" --json --verbose --events | grep -o '"node_output": "x*"' | tr -cd 'x' | wc -c
```

### Observed

```text
203
5000
```

The node summary holds 200 characters and `...`; only the raw `node_completed` event holds all 5000.

### Expected

The documented JSON for the run gives the node's 5000-character output.

### Environment

- Archon version or commit: CLI v0.13.2 release binary (`archon-windows-x64.exe`, commit b8d01782). The code path below is unchanged on `dev` at 755cfad79ac8.
- Platform or adapter: CLI
- Database: SQLite
- OS: Windows 11 x64, Git Bash

## Constraints and related work

- Must remain true: persisted node output stays bounded (`PERSISTED_NODE_OUTPUT_MAX_BYTES`, 32 KiB, with larger bash and script output spilled to a file), and raw events stay a debugging surface.
- Related issues or PRs: none found.
- Solution steering: Hint. `outputPreviewOf` in [`packages/cli/src/commands/workflow-node-summaries.ts`](https://github.com/coleam00/Archon/blob/755cfad79ac8c66b03768479fcf7acdcab8691a3/packages/cli/src/commands/workflow-node-summaries.ts#L101-L104) cuts `node_output` to 200 characters for both summary paths ([L215](https://github.com/coleam00/Archon/blob/755cfad79ac8c66b03768479fcf7acdcab8691a3/packages/cli/src/commands/workflow-node-summaries.ts#L215) and [L274](https://github.com/coleam00/Archon/blob/755cfad79ac8c66b03768479fcf7acdcab8691a3/packages/cli/src/commands/workflow-node-summaries.ts#L274)), and the summary has no field for the full text. An `output` field on verbose JSON node summaries, or an option that prints one node's output, would cover this.
