# Ensure SSE heartbeat test cleanup runs when response setup fails

Filed by app/coderabbitai.

## Summary
The `SSE heartbeat lifecycle` tests in `packages/server/src/routes/api.messages.test.ts` install spies before calling `app.request`, validating the response body, and creating the response reader. These setup operations occur before the existing `try` block.

If the request rejects, the response body is missing, or reader creation throws, the `finally` cleanup does not run. Prototype spies can remain installed and affect later tests in the same Bun process.

## Required changes
- Move the request, response-body validation, and reader creation inside the cleanup-protected `try` block.
- Track the reader as optional and cancel it only if reader creation succeeded.
- Ensure setup failures cannot bypass spy restoration and transport cleanup.
- Keep the existing heartbeat lifecycle assertions for conversation and dashboard streams.

## Acceptance criteria
- Request rejection, a missing response body, and reader-creation failure cannot leave the test spies installed.
- Teardown remains safe when no reader was created.
- Existing abort, close, and heartbeat-error test cases retain their coverage.
