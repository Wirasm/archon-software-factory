# feat: worktree.linkFiles — symlink git-ignored dirs instead of copying

Filed by fcamblor.

## Problem

- When using `worktree.copyFiles` with large git-ignored directories (LSP caches, runtime logs, metadata stores), Archon physically copies them into each worktree. This wastes disk space and slows worktree creation.
- Affects any user whose tooling stores runtime state in git-ignored subdirectories (e.g. Serena LSP cache, Entire search metadata).
- Comes up every time a new worktree is created.

## Proposed Solution

Add a `worktree.linkFiles` config option that creates symlinks instead of copies.

## User Flow

### Before (current)

```
worktree:
  copyFiles:
    - .serena/cache       # [!] copies potentially hundreds of MB per worktree
    - .entire/logs        # [!] duplicates data that should be shared
```

### After (proposed)

```
worktree:
  copyFiles:
    - .claude/settings.local.json   # small file, copy is fine
  linkFiles:                        # [+] symlinked, not copied
    - .serena/cache
    - .entire/logs
    - .entire/metadata
```

## Alternatives Considered

| Alternative | Pros | Cons | Why not chosen |
|-------------|------|------|----------------|
| Manual shell script calling `ln -s` | Works today | Not integrated, must be run manually after each worktree creation | UX friction |
| `copyFiles` for everything | Simple config | Wastes disk, slow on large dirs | Doesn't scale |
| Symlink the whole parent dir | Simple | Conflicts with git-tracked files inside the same dir | Git manages tracked files, symlink would shadow them |

## Scope

- Breaking change? No
- Database changes needed? No

## Discussion


**Wirasm** (collaborator, 2026-10-19):

Still true on dev: worktrees only support `copyFiles`. A `linkFiles` option makes sense for large caches. One thing to settle in the design: a symlinked directory is shared by every worktree, so two runs writing the same cache at once can step on each other. We'll keep this open as a feature request, and a PR that documents that trade-off is welcome.
