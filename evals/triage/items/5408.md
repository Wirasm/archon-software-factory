# Console run view: show each node's model, provider and effort, and per-model totals

Filed by robertmeisner.

## Problem

The console's run view already shows each node's duration, turns, cost and input/output tokens (`NodeDivider`), and the run's duration and cost (`RunLifecycle`). What it does not show is **which model ran each node**, so when one run is slow or expensive I still have to read `archon workflow get <run-id> --verbose --json` to see whether that node ran on a large or a small model, at which effort, and whether it continued an earlier session.

Archon already records all of this per node execution:

- `execution.binding`: `provider`, `model.requested` and `model.resolved`, `effort`, `sessionOrigin` (fresh or continued)
- `execution.spend.tokens`: `input`, `output`, `cacheRead`, `cacheWrite`
- `execution.spend.costUsd`, `numTurns`, `stopReason`, each with a `source` that says when the provider does not report it
- `execution.attempt` and `invocation.loopPath`

## Proposal

1. **Per node, next to the existing duration and cost:** the model (requested, and resolved when known), provider and effort, and whether the session was fresh or continued. In the node's details: the cache read and cache write tokens, the stop reason, the attempt number, and the loop iteration for a node inside a `loop_group`.
2. **Missing values:** a value whose `source` is `unavailable` shows as "not reported" instead of being left out, so a provider that reports no cost (Codex today) is not mistaken for a node that cost nothing.
3. **Per run:** total tokens next to the reported cost, and the same totals per model, so a run that mixes providers shows what each model used.
4. Wherever a run is drawn as a graph (#5343), each node box shows its model next to its duration.

## Acceptance

- [ ] Every executed AI node in the run view shows its provider, model and effort, matching `archon workflow get <run-id> --verbose --json`.
- [ ] A field whose `source` is `unavailable` reads "not reported".
- [ ] The run shows total tokens and a per-model breakdown of tokens and cost.
- [ ] A node inside a `loop_group` shows its iteration and attempt.

## Related

- #5343: a run graph with live node state; item 4 applies to it once it exists.
- #2801: tokens per second per model, which could use the same per-model breakdown.

Happy to send a small PR for the run view if this direction is welcome.
