# feat(providers/codex): gateway routing parity with #2185 — OpenAI-compatible baseUrl per alias

Filed by exploredata10.

## Summary

Field-tested companion to #2185 (Claude alias-scoped gateway routing). During a local-first integration against an OpenAI-compatible gateway (LiteLLM + ODS privacy-shield, one URL + one key serving NIM/OpenRouter/local models), the Codex stack turned out to have **no equivalent seam** (OpenCode, which had the same gap, is deprecated, #3684, and is out of scope):

- **Codex**: subprocess reads `CODEX_HOME/config.toml`; custom `model_providers` entries (`base_url`, `wire_api="chat"`) are supported upstream by the CLI but Archon never writes/plumbs them. `OPENAI_BASE_URL` alone is insufficient.

## Proposal

Parity with #2185 for Codex:

```yaml
aliases:
  "@gateway-fast":
    provider: codex
    model: nim-fast
    baseUrl: http://localhost:8085/v1
```

- Codex: render the resolved `baseUrl`/key into a managed `CODEX_HOME` overlay at session spawn (same isolation pattern already used for auth.json).
- Credentials via vault as in #2185 — never in config files.

## Prerequisite / related (external)

The ODS privacy-shield currently proxies **OpenAI wire format only** (`/v1/messages` with `x-api-key` fails; verified live). Anthropic-protocol traffic therefore bypasses PII scrubbing until the shield adds `/v1/messages` passthrough/translation. Codex parity is unaffected (OpenAI format end-to-end).

## Evidence

- LiteLLM `/v1/chat/completions` + shield :8085: verified live (chat, streaming, tool-calls).
- Shield `/v1/messages`: `{"detail":"Missing Authorization header"}` — no Anthropic path support.
- Pi stack needs nothing here: custom providers from `~/.pi/agent/models.json` already work through `provider: pi` (syntactic-only ref validation in `model-ref.ts`); worth documenting separately.

## Priority rationale

For single-operator/local-first installs this unlocks every free-tier endpoint behind one governed URL/key across agent stacks, not just Claude. Requesting **P1** alongside #2185.


## Discussion


**Wirasm** (collaborator, 2026-10-04):

Narrowed to Codex: OpenCode is deprecated (#3684), so the OpenCode half is dropped from the title and body (the original is in the edit history). This stays a design issue behind #2185.

Direction recorded: the gateway setting lives in provider config, not on an alias. A gateway is how you reach a provider, not which model you pick, so a `baseUrl` and its credential reference belong with the provider's settings (and the credential vault), and an alias or tier only chooses a provider and model. This is settled once for both #2185 (Claude) and this issue (Codex), so the two do not grow different shapes. The `aliases:` example in the body shows the original proposal and is superseded by this.
