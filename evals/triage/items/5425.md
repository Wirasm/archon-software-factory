# Docs: an answer given in a terminal can continue inside a running `archon serve`, but the docs say it continues in place

Filed by Pateng-Peng.

## Problem

The pages an operator reads before answering a gate say the terminal continues the run:

- [`getting-started/operate.md:70`](https://github.com/coleam00/Archon/blob/8def159a6b2c23e832a5283b4131cfffd9af9344/packages/docs-web/src/content/docs/getting-started/operate.md?plain=1#L70): "In a terminal, an answer continues the run in place."
- [`reference/cli.md:1139`](https://github.com/coleam00/Archon/blob/8def159a6b2c23e832a5283b4131cfffd9af9344/packages/docs-web/src/content/docs/reference/cli.md?plain=1#L1139): "In human mode `approve`/`reject` auto-resume the run inline."

The source adds a condition these pages leave out. The answering command records the answer first, then claims the run. A continuation host on the same database can claim it first, because an answered gate or attention wait is a due continuation for its scan:

- [`packages/cli/src/commands/workflow-control.ts:298-302`](https://github.com/coleam00/Archon/blob/8def159a6b2c23e832a5283b4131cfffd9af9344/packages/cli/src/commands/workflow-control.ts#L298-L302): "A continuation host may claim the answer first; `workflowRunCommand` reports that and returns." `answer`, `approve`, `reject` and `respond` all continue through it (`:436`, `:545`, `:656`, `:760`).
- [`packages/core/src/db/workflow-run-waits.ts:158-167`](https://github.com/coleam00/Archon/blob/8def159a6b2c23e832a5283b4131cfffd9af9344/packages/core/src/db/workflow-run-waits.ts#L158-L167) and `:184-185`: the scan selects a paused run whose approval is resolved, and one whose attention wait has an answer.
- [`packages/server/src/services/workflow-resume-service.ts:18`](https://github.com/coleam00/Archon/blob/8def159a6b2c23e832a5283b4131cfffd9af9344/packages/server/src/services/workflow-resume-service.ts#L18): `archon serve` scans every 5 seconds.
- [`packages/cli/src/commands/workflow-run-owned.ts:144-155`](https://github.com/coleam00/Archon/blob/8def159a6b2c23e832a5283b4131cfffd9af9344/packages/cli/src/commands/workflow-run-owned.ts#L144-L155): when the CLI loses, it prints `Run <id> is already continuing in another process.` The comment at `:149` names "an approve that lost the claim to `archon serve`".

So while a server runs, the run continues either in the answering terminal or in the server's process, whichever claims first. Only the `workflow wake` section names the claim ([`reference/cli.md:1445`](https://github.com/coleam00/Archon/blob/8def159a6b2c23e832a5283b4131cfffd9af9344/packages/docs-web/src/content/docs/reference/cli.md?plain=1#L1445): "Concurrent CLI and server hosts use the engine's existing occurrence claim, so only one executes a continuation."). The answering commands' own sections do not.

## Why

Where a run continues decides which process it lives in. An operator may run `archon serve` only for the Web UI, for a shorter time than the run takes, and answer gates in a terminal. Going by the docs, that operator expects the terminal to carry the run. When the server wins the claim, the run executes in the server's process, and the terminal prints one line and returns.

## Desired outcome

The docs for answering a gate or an attention wait in a terminal (`operate.md`'s answer paragraph, and `workflow approve`, `reject`, `respond` and `answer` in `cli.md`) say three things: a continuation host running on the same database may claim the answered run first; the run then continues in that host's process; and what the terminal prints.

## Acceptance

- [ ] `getting-started/operate.md` states the condition beside "In a terminal, an answer continues the run in place."
- [ ] `reference/cli.md` states it for `workflow approve`, and for `reject`, `respond` and `answer`, which continue the same way, with the line `Run <id> is already continuing in another process.`

## Evidence

### Reproduction

Read from the source and from Archon's own test, [`packages/cli/src/commands/workflow-store.integration.spec.ts:461-479`](https://github.com/coleam00/Archon/blob/8def159a6b2c23e832a5283b4131cfffd9af9344/packages/cli/src/commands/workflow-store.integration.spec.ts#L461-L479) ("approve reports a run the continuation host claimed first as continuing elsewhere"). Not reproduced on a host. The test's shape:

1. A run pauses at an approval gate.
2. A continuation host (`archon serve`, or `archon workflow wake --watch`) runs against the same database.
3. `archon workflow approve <run-id>` in a terminal records the answer. If the host claims the run first, the CLI prints `Run <run-id> is already continuing in another process.` and returns, and the run continues in the host.
