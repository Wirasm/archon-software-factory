# Feature Request: Set repo worktree base branch from the Web UI

Filed by xogno.

## Problem

An operator who wants Archon worktrees to start from `dev` instead of `main` has to edit `.archon/config.yaml` by hand and set `worktree.baseBranch`. The console has no place to see or change it. `packages/web/src/experiments/console/primitives/project.ts` only reads the codebase `default_branch` (falling back to `main`), and there is no route to change a codebase's branch: `/api/codebases/{id}` has no PATCH in `packages/server/src/routes/api.ts`. The setting is read from the repo config at `packages/core/src/config/config-loader.ts:736`.

## Why it matters

Teams that branch from `dev` hit this on the first run. Operators who work through the console may not have a shell on the machine hosting the checkout, so the file edit is not available to them. A wrong base branch silently produces worktrees off the wrong history.

## Desired outcome

A project's worktree base branch is visible and editable from the console project settings, and the value shown is the one Archon actually uses when it creates a worktree.

## Invariants

- One source of truth. Decide first whether the value lives in the repo `.archon/config.yaml` (`worktree.baseBranch`) or in the codebase row (`default_branch`), and make the console read and write that one place. Related: #2593 (`default_branch` stores a local branch).
- When unset, current auto-detection is unchanged.
- A configured branch that does not exist on the resolved remote still fails with the existing error (`docs/reference/configuration.md`, no silent fallback). The console should surface that error, or warn at save time.
- The change goes through an API route and generated types; the console does not edit repo files directly.

## Acceptance

- The console project settings show the effective base branch and where it comes from.
- Saving a branch changes the base of the next worktree created for that project.
- Clearing the field restores auto-detection.
- The saved value is shown again after a reload.
- An unknown branch produces a visible message, not a silent fallback.
