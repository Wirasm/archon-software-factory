# Console: run lists and the run page never show the date or time a run started, only its duration

Filed by robertmeisner.

## Problem

The console never shows the date a run started. Run lists and the run header show only how long the run took, and the run page shows the start as a time of day without a date. For runs from earlier days, or several runs of the same workflow, there is no way to tell from the console when each run happened, which makes it hard to correlate a run with logs, commits or other runs.

## Where it happens (main at 442c90f)

- `packages/web/src/experiments/console/components/RecentRunRow.tsx:37`: the row shows `formatElapsed(elapsedSince(run.startedAt, run.finishedAt))`, the duration only.
- `packages/web/src/experiments/console/components/RunDetailHeader.tsx:30`: the header shows the same duration only.
- `packages/web/src/experiments/console/components/RunLifecycle.tsx:20`: the start line uses `formatClock(run.startedAt)`, which (`lib/format.ts:71`) renders `HH:MM:SS` with no date.
- `lib/format.ts:43` already has `relativeTime()`, which no run view uses.

## Steps to reproduce

1. Open the console's run list for a project that has runs from an earlier day.
2. The rows show durations such as `04:12`, but no start date or time.
3. Open one of those runs: the header shows the duration, and the log's first line shows only a time such as `13:31:28`.

## Proposal

- In run list rows, show when the run started next to its duration: a relative time (`relativeTime`, for example "2 h ago", "yesterday") with the full local date and time in a `title` tooltip, so the row stays compact.
- In the run detail header, show the start date and time in local time (for example `Nov 8, 13:31:28`) next to the duration, and the finish time for finished runs.
- Let `formatClock` include the date when the timestamp is not today (or add a `formatDateTime` helper), so the run lifecycle line is unambiguous too.

Tests can freeze the clock and check the rendered text for a run started today, yesterday and last week, in a non-UTC time zone (#1990 fixed the UTC normalisation the helpers rely on).
