# Slack: select attention answers can't carry text, so the SDLC queue's "Something else" always resumes with no ruling

Filed by openmikeclaw.

## Problem

In Slack, a `select` attention wait renders each option as a plain button. A click answers at once with `choose: [id]` and no text. There is no way to add text from Slack.

The bundled SDLC build queue depends on that text. Every stop decision offers `other` ("Something else"), and its description says: "Do what the answer text says. The text is written into the issue body as the ruling, and the next round works from it." From Slack, this choice always resumes with `text: ""`. The `ruling` script then writes no ruling, and the next round stops again and asks the same question.

A reply in the notice's thread does not help: the thread reply is not read as the answer text.

## Why

Slack is the main way an operator answers attention away from the console. The "Something else" choice can never work from Slack, and each attempt costs a full round. The person also gets no warning that their text was not recorded.

## Desired outcome

From Slack, a person can answer a `select` wait with an option and text, as the web console already allows (`AttentionAnswerPanel` shows "Optional text" for `select`).

## Acceptance

- [ ] From Slack, a person can choose an option of a `select` wait and add text. The answer's `text` holds that text.
- [ ] Choosing `other` in the SDLC queues from Slack writes the person's text into the issue body as the ruling.
- [ ] A one-click answer with no text still works for options that need no text.

## Evidence

### Reproduction

1. Run `archon-build-queue` (bundled SDLC) until it pauses at a stop decision in Slack.
2. Click "Something else".
3. The notice settles as "Chose other by @user (workflow resumed)". The work item's recorded answer is `{"choice": "other", "text": ""}`, and the next round stops with "Your last answer had no text, so the build has no ruling."

### Environment

- Archon version or commit: v0.13.2 (`chat-slack` plugin at `b8d01782`)
- Platform or adapter: Slack
- Database: SQLite
- OS: macOS

### Logs or screenshots

From the work item state after the click: `"answer": { "choice": "other", "text": "", ... }`.

## Constraints and related work

- Must remain true: options that need no text stay one click.
- Related issues or PRs: #2822 (gate decisions rendered on every interactive surface), #2707 (one pause primitive, input channels).
- Solution steering: Hint — `packages/chat-slack/src/blocks.ts` `noticeControls` already has the compose modal (`NOTICE_COMPOSE`, `buildComposeView`) that the `message` form and the interactive-loop "Reply" use, and `onCompose` already sets `response.text`. One option is an "Answer with text" button on `select` waits that opens a modal with the options and a text input. Another is to let a workflow mark an option as needing text (for example the queue's `other`), so that option's button opens the compose modal.
