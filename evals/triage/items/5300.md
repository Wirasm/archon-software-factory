# Clarify the properties condition for Codex required-field diagnostics

Filed by app/coderabbitai.

## Summary

Clarify the Codex strict-mode object schema documentation. The current wording promises named-field diagnostics for required names absent from the prepared object's properties without stating the condition for that diagnostic.

The wording and implementation are already present on dev. Track this clarification separately from the workflow-status read work in PR #5294, as requested by @Wirasm.

## Affected areas

- `packages/docs-web/src/content/docs/reference/workflow-language.md`, in “Codex strict-mode object schemas” (currently Line 596).
- Reference implementation: `packages/provider-contract/src/strict-output-schema.ts`. The required-name check runs only when `isRecord(node.properties)` is true.

## Required change

State that Archon reports required names missing from prepared properties only when the object declares a record-valued `properties` field. Keep the surrounding explanation unchanged. Do not change schema normalization or validation behavior.

An object with `required` but no `properties` does not receive this named-field diagnostic. The documentation must distinguish that case from an object with declared properties.

## Acceptance criteria

- The named-field diagnostic claim includes the `properties` condition.
- The existing explanation of missing `properties` and missing `required` remains intact.
- The wording matches the implementation on dev.
- No runtime or schema-handling changes are introduced.
