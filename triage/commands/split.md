# Should this item be split?

Triage said this item should be built. Decide whether it is built as one piece of work, or broken into the fewest pieces that each prove something on their own.

The item:

$INPUTS.item

What triage concluded about it:

$judge.output

Start from one piece. One run can plan and deliver a large change, and one change for one outcome is easier to check than several that only make sense together. Split only for a reason the item itself shows:

- its pieces are separate outcomes, each worth having on its own;
- a piece must land and be used before a later piece can be built or judged;
- the work spans so many parts and surfaces that no single run could finish it.

Length, a long acceptance list, a large size, vagueness, and a title that says PRD or epic are not reasons. They are reasons to plan carefully.

When you split, name only what should start now: the smallest piece that proves the next thing, often one. Say what comes later and the signal the earlier work must show before it starts. Do not cut by layer or by file: each piece leaves the product working and shows something a person can observe.
